## 1. Executive Summary

Phase 4 of Project Zahra represents a fundamental qualitative evolution in the assistant's architectural depth. Operating strictly under the **Truth Before Intelligence** mandate with zero external APIs, zero LLMs, zero cloud dependencies, and zero background network calls, Zahra now features:

1. **Robust Multi-Dialect & Mixed-Language Understanding:** Transparent normalization of Egyptian colloquial Arabic ("عايز اعرف", "معلش احسبلي", "بقولك ايه"), Modern Standard Arabic, English commands ("calc", "convert", "translate", "what is"), and mixed Arabic-English phrases without semantic degradation.
2. **Ambiguity and Clarification Detection:** Explicit identification of underspecified requests (e.g. missing units in conversions, missing time/action in scheduling) providing structured, concise clarification choices instead of hallucinating parameters.
3. **Multi-Turn Context & Dynamic User Correction:** Tracking short-term conversational context across turns, enabling follow-up questions ("وماذا عن..."), explicit rollbacks ("تراجع"), and transparent fact corrections ("اسمي مش محمد، اسمي علي") that update permanent memory while explaining detected conflicts.
4. **Bounded Deterministic Reasoning Engine:** Modular deductive engine operating on typed facts and inference rules with strict, non-negotiable safety limits: maximum 50 derivation steps, maximum depth of 5, recursion/cycle guards, and complete provenance tracking linking every derived conclusion to its source premise IDs.
5. **Contradiction Detection & Source Priority Policy:** Identifying value mismatches between incoming statements and stored facts with an unambiguous priority hierarchy: Explicit User Input > Inferred Context; Canonical Curated Records > Unverified Claims.
6. **7-Stage Epistemic Grounding Pipeline:** Every response generated by Zahra produces an inspectable, typed evidence trace (`VERIFIED`, `USER_SUPPLIED`, `LOCAL_CURATED`, `DEDUCTION`, `ESTIMATE`, `UNKNOWN`) that clearly separates user premises, active rules, derived conclusions, and remaining uncertainty.
7. **Safe Action Execution:** Precondition parameter validation, 30-second window idempotency deduplication to prevent accidental double-submits, postcondition verification, and confirmation barriers for destructive actions.
8. **Islamic Knowledge & Ethical Safeguards:** Uncompromising adherence to authentic primary sources (Quran and authentic Hadith) when responding to well-established Islamic prohibitions (usury/riba, gambling/maysir, fraud/cheating, and intoxicants), refusing to fabricate hadith gradings or invent religious rulings without recorded attribution.

## 3. Detailed Architecture and Implemented Components

### 3.1 Understanding & Dialog Flow (`com.example.zahra.understanding`)
- **`DialectAndColloquialAdapter`**:
  - Automatically identifies and strips conversational filler prefixes ("معلش", "بقولك ايه", "طب تمام", "يا ريت", "ممكن بعد إذنك", "هو يعني ايه").
  - Maps Egyptian intent triggers ("عاوز اعرف", "نفسي اعرف", "قولي كدة", "وريني") to canonical intents (`query_knowledge`, `define_word`).
  - Handles English direct commands (`calc`, `convert`, `translate`, `summarize`, `what is`, `add task`, `remind me`, `tasks`, `notes`, `schedules`).
- **`AmbiguityAndClarificationDetector`**:
  - Analyzes requests for missing parameters (e.g., unit conversions lacking target units, scheduling commands lacking specific time).
  - Emits structured `ClarificationPayload` with 2–3 concise, single-tap options for the user interface.
- **`ContextAndCorrectionTracker`**:
  - Maintains a rolling 5-turn dialog buffer.
  - Recognizes user corrections ("لا، أنا اسمي...", "اسمي مش X اسمي Y", "قصدي...", "تراجع") and connects follow-up inquiries ("وماذا عن...") to the antecedent subject.

### 3.2 Bounded Deterministic Reasoning (`com.example.zahra.reasoning`)
- **`ReasoningEngine`**:
  - Evaluates typed facts (`TypedFact`) using deterministic inference rules (`InferenceRule`).
  - Strict bounded execution: `maxSteps = 50`, `maxDepth = 5`, loop detection via signature sets, and execution timeout protection.
  - Complete provenance tracking: Every derived fact stores the IDs of its antecedent premises and the rule that generated it.
- **`ContradictionDetector`**:
  - Compares new facts against active memory to detect conflicts (`DIRECT_VALUE_MISMATCH`).
  - Implements source priority hierarchy (`USER_EXPLICIT` > `INFERRED_OBSERVED`; `CANONICAL` > `UNVERIFIED_CLAIM`).
  - Transparently explains conflicting facts to the user rather than silently overwriting them.
- **`EpistemicGroundingPipeline`**:
  - Generates a 7-stage inspectable evidence trace separating:
    1. Raw user request
    2. Extracted understanding & parameters
    3. Verified context facts
    4. Deterministic rules applied
    5. Derived facts with typed certainty (`VERIFIED`, `USER_SUPPLIED`, `LOCAL_CURATED`, `DEDUCTION`, `ESTIMATE`, `UNKNOWN`)
    6. Remaining uncertainty & limitations
    7. Final transparent response text

### 3.3 Safe Tool Execution (`com.example.zahra.execution`)
- **`SafeActionExecutor`**:
  - Enforces strict precondition validation for task creation, note storage, and scheduling.
  - Idempotency guard: Computes SHA-256 action payload signatures and rejects duplicate rapid submissions within a 30-second window.
  - Postcondition verification: Validates storage persistence before declaring operation success.

### 3.4 Islamic Knowledge & Ethical Integrity (`ReligionEngine`)
- Direct and respectful refusal with authoritative evidence when queried about well-established prohibitions:
  - Usury / Riba: Citing Quran 2:275 (سورة البقرة: 275).
  - Gambling / Maysir: Citing Quran 5:90 (سورة المائدة: 90).
  - Fraud / Cheating: Citing Sahih Muslim (حديث: «من غشنا فليس منا»).
  - Intoxicants / Alcohol: Citing Quran 5:90 and Sahih Muslim 2003 (حديث: «كل مسكر خمر، وكل مسكر حرام»).
- Strict adherence to authentic attribution: Refuses to fabricate hadith gradings or invent unverified statements, responding with `UNSUPPORTED` / abstention when text is absent from the verified local database.
